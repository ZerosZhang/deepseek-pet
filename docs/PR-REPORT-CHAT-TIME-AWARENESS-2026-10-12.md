> **基线**：`ee699c7`（Merge PR #233 feature/agent-link-subtraction）
> **分支**：`feat/chat-time-awareness`　**日期**：`2026-10-12`
> **范围**：5 个文件（实现 1、测试 3、文档 1 + INDEX 登记）
> **关联**：无

## 一、核心特性

会话文件里每条消息本来就记录了 `created_at`（UTC ISO 时间），但 `PromptBuilder.build_messages` 只把 `role/content` 发给模型，
模型因此不知道「现在几点」「上次聊天是多久以前」，隔了一周回来它仍当作刚才在聊。本 PR 只在**组装请求**时附加时间信息，
不改会话文件、不迁移旧数据——旧会话立刻生效。

| # | 能力 | 说明 |
|---|---|---|
| 1 | 当前时间 | system 末尾追加「【时间信息】当前时间：2026-10-12 周一 02:14」（本地时区） |
| 2 | 距上条消息的间隔 | 「距离上一条消息（2026-10-04 周日 08:28）已经过去约 7 天 17 小时」；10 分钟内视为连续对话，不提示 |
| 3 | 历史用户消息带发送时间 | 用户消息内容前加 `[2026-09-15 周二 00:05] `；**助手消息不加**，避免模型在回复里模仿时间标记 |

**红线 / 不变量**：会话落盘内容不变（只在发给模型时附加）；`created_at` 无法解析的旧/坏数据原样发送、不抛错；
本轮用户输入原样（当前时间已在 system 里）；`effective_system_prompt()`（用于写入会话的 system_prompt 字段）不变。

## 三、实现要点

- 时间统一 `datetime.fromisoformat(created_at).astimezone()` 转本地时区：naive 值视为本地时间；跨夏令时的历史消息也能得到正确的本地钟点
  （因此没有用「当前时区偏移」做固定换算来省时间，见第四节）。
- 只标用户消息：实测/经验上模型会模仿上下文里助手消息的格式，助手消息带标记容易让回复也以 `[日期]` 开头。
- 提示词里明确「不要在回复中复述或模仿这种时间标记」。

## 四、性能分析

**方法（可复现）**：40 条历史（20 轮，间隔 1 小时）+ 本轮输入，`build_messages` 调 2000 次取中位；基线与本分支 `git stash` 交替。
环境：Windows 11 Pro 22631 / AMD Ryzen 7 7800X3D / Python 3.11.5

| 指标 | 基线 | 本分支 | 归属 |
|---|---|---|---|
| `build_messages` 中位 / p90 | 8.6 / 9.0 µs | 198.0 / 249.2 µs | 每次发送消息执行一次 |
| 请求总字符数（42 条消息） | 1981 | 2601（+620，+31%） | 每次请求 |
| system 字符数 | 28 | 208 | 每次请求 |

**结论**：① 稳态零开销（只在发送时执行）；② 组装耗时 +0.19 ms/次，主要是每条消息 `astimezone()` 查询本地时区——相对一次
网络请求（百毫秒级）可忽略，未为它牺牲跨夏令时的正确性；请求体变长：本样例 +620 字符（system 约 180 字 + 每条用户消息约 22 字的时间前缀），
会相应增加输入 token；③ 无新的系统调用（`astimezone` 读本地时区）、网络、磁盘或线程；④ 无内存增长（不缓存）。

## 五、实机运行记录

- **根因确认（本机，只读元数据）**：用户真实会话目录 10 个文件、85 条消息，**每条都有 `created_at`**（最早 `2026-09-12T08:31:40+00:00`，最晚 `2026-10-03T23:28:48+00:00`）——问题不在记录，而在没发给模型。
- **真实会话预览（不输出聊天内容）**：用户最长会话（67 条）经 `build_messages` 后，system 末尾为
  `【时间信息】当前时间：2026-10-12 周一 02:14。距离上一条消息（2026-10-04 周日 08:28）已经过去约 7 天 17 小时。…`；
  历史用户消息前缀 `[2026-09-14 周一 16:41]`、`[2026-09-15 周二 00:05]` 等（已换算为本地 UTC+8），助手消息无前缀。
- **用户可见行为**：本机打包版已安装含本功能的构建并日常使用（2026-10-12 起）；用户未专门反馈时间感知的效果，
  因此这里不登记用户确认——模型实际回复中是否自然体现时间流逝，以上面的请求内容预览为准。
- **旧数据不被改写**：用例按用户磁盘格式写会话文件，读入并构建消息后文件字节不变。

## 七、已知限制与后续

- 没有设置开关：时间信息对所有使用 `build_messages` 的对话生效。若维护者希望可关闭，可在 `ChatSettings` 加一个默认开启的布尔键，
  `build_messages` 据此跳过——改动很小，按评审意见补。
- 本轮用户输入不带前缀（当前时间已在 system 中），因此「历史里最后一条用户消息」与「本轮」的时间对照依赖 system 的「当前时间」。
