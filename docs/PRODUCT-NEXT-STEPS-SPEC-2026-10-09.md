## 一、身份与生命周期（多宠）

- **【裁决】身份空间稳定且固定**：`slot0` 主宠、`slot1`/`slot2` 子宠。槽位是"宠物档案的地址"，
  不是"当前谁最大"的排名。
- **【裁决】关闭宠物 = 该槽留空，档案保留**。留空只表示"这个位置现在没有宠"，不表示档案失效。
  **【现行】** `pet/overlay_shell.py:3933` 的 `_exit_main_pet`：无子宠时直接 `app.quit()`（关宠 = 退应用），
  有子宠时把 `_spawned[0]` **提升**为主身份并把它的 per-slot 键写进主配置。**该提升语义被废除。**
- **【裁决】生成取最小非活跃槽（含 0）**。若该槽有档案，**优先恢复档案中的角色与位置设置**——
  "恢复"不是"覆盖"：档案只经该槽自身运行期几何自存或用户主动设置而改变。
  **【现行】** `pet/overlay_spawn_state.py:178` `allocate_slot`：取最小空闲 `N ≥ 1`（不含 0），
  名额用尽时**复用最小退役身份并覆盖其位置/设置记忆**（只留一条 warning）；`normalize_slots`（同文件 `:88`）
  丢弃 `slot < 1`。这三处都要改。
- **【裁决】身份空间是 `0..128`（含）且只扩不缩**：现行上界 `MAX_SCAN_SLOTS = 128`，
  `config-slot-128.json` 是一个**已经合法存在**的身份；把分配范围收成 `0..127` 会让既有 `slot128`
  因"容量收缩"被丢弃或复用，**禁止**。分配范围是含 0 的 `0..MAX_SCAN_SLOTS`（当前即 0..128，共 129 个身份）。
  **这不是"无限槽位"新需求**：上界仍是一个固定常量，只是**不得改小**；将来要动只能**扩大**，并单独过设置门禁。
- **【裁决】永不提升、永不重命名**：没有任何路径可以把一只宠的身份"接管"成主身份。
- **【裁决】不覆盖档案**：**不以其他宠的档案替换本槽的档案**——"不覆盖"禁止的是**跨身份替换**，
  不是禁止本槽写入。**本槽用户的编辑与正常保存是允许的**：用户改这只宠的设置、这只宠自存几何，
  都写回本槽自身档案。
- **【裁决】旧覆盖无备份、不能找回**：历史遗留的跨身份覆盖**不得**尝试自动修复（没有可信来源），只如实报告。
- **【裁决】活跃集合的持久化与迁移**：**新安装默认 `slot0`**；新格式下活跃集合为空就**保持为空**
  （空集合是合法状态，不得静默补一只）；从旧格式迁移时**给旧集合补上 0**，且**迁移先备份、可重跑（幂等）**。
  **【现行】** `pet/overlay_spawn_state.py` 的 `load_active_slots` 把"文件缺失"与"文件损坏"一律当
  "只有主宠"处理——新格式下这两种情况要分开：缺失按新安装默认（`slot0`），损坏/为空就是空。
  **【裁决】三种输入的结果是确定的，不得按"看起来像新安装"自行选择**：
  ①**旧格式（v1）文件存在、`slots` 为空 `[]`** → 迁移结果 **`[0]`**（旧格式一律补 0；"空"在旧格式里
  不是合法状态）；②**新格式（v2）文件存在、`slots` 为空 `[]`** → **保持 `[]`**，**不得复活任何宠**；
  ③**文件缺失** → 按新安装默认 `slot0`。**"旧格式空集合"与"新格式空集合"必须分别判定、分别处理**，
  把它们合并成一句"空就是空"即违反本节。
- **【裁决】全局服务由应用持有，与 slot0 解耦**：agent_link / proactive / 全屏监测 / 会话等由应用层持有并
  存活；slot0 缺席（关闭或隐藏）**不得**顺带拆掉这些服务，也**不得**因此改变任何槽的身份。
- **【裁决】自动全局提示的落点**：优先可见的 `slot0`；`slot0` 缺席或隐藏时，由**最小可见槽临时显示**，
  **不改身份**（临时落点不获得主身份、不迁移档案、不改会话角色）。
- **【裁决】手动互动归发起槽**：谁被点、谁被拖、谁发起对话，结果就归谁。
- **【裁决】关闭后的迟到结果**：槽关闭后，迟到结果**只取消宠物呈现**（不再弹到任何宠身上、不改别宠状态）；
  **共享会话里已经生成并落库的消息不因此丢弃**——那是会话的事实，不是宠物呈现。
  **同一槽被重建也需要代次**（slot 序号相同 ≠ 同一只宠），否则迟到结果会投给新住客。

## 二、会话、显示锚与角色

- **【裁决】默认聊天维持现有共享会话**：不暗增"每宠一个会话"。
- **【裁决】不以"会话是共用的"为由禁止子气泡点击**：共享会话是**会话**维度的裁决，
  不是**交互**维度的禁令。
  **【现行】** `pet/overlay_shell.py:2549` `_apply_bubble_interactive` 只把主气泡 follower 设为可点，
  子气泡（`_bubble_followers`）不接；`_on_bubble_clicked`（同文件 `:2555`）已按发起 sprite 打开快速对话。
- **【裁决】显示锚与角色/会话语义必须清楚分离**：气泡挂在谁旁边（显示锚）与"这段对话属于谁、用谁的人设"
  是两件事；**不能因为发起者换了就悄悄改共享会话的角色**。
- **【裁决】共享会话的角色 = `slot0` 档案里选定的角色**：由 `slot0` 自己的档案决定；**`slot0` 关闭（留空）
  不改变它**（槽留空，档案仍在，会话角色照旧）；**子宠切自己的角色不改共享会话角色**。这是"一份会话、
  一个角色"的表述，**不是每宠独立人格**。
- **【裁决】界面必须说清这一点**：凡让用户以为"每只宠都有独立对话人格/独立会话"的措辞都要改；
  UI 只承诺"子宠可以发起并接着聊"，不承诺"独立人格"。

## 三、全局事件、提醒与去重

- **【裁决】全局事件一份监测、一次门控、一个正文展示落点、至多一次提示音**：
  同一逻辑事件只允许一个正文落点；灵动岛状态可以**同步**该事件但**不重复正文**。
- **【裁决】主位恢复只改后续事件**：显示落点从临时槽回到 `slot0` 时，**不重播**已发生过的事件、
  **不重复**提示音（交接只影响此后新产生的事件）。
- **【裁决】在途常驻提醒在**同一次运行内**保持 event 身份直到 resolved**：常驻/待处理提醒在解决前保持同一
  事件身份，**不复活已解决提醒**（重复出现 = 缺陷）。**不把"跨重启持久化提醒队列"当作需求**：重启后只按
  **各源当前的有效状态**重建（源说还有就重建、源说没了就不重建），**不保证旧队列原样恢复**。
- **【裁决】去重优先级 = 源 ID 优先**：能用源自身的 ID 就用它；**源没有 ID 时**，用**经验证的**会话状态代次 /
  读取游标等进程内标识；**不声称这些标识来自上游**——它们是我们自己的记录口径，文档与日志都如实标注。
- **【裁决】去重键 = 来源 + 会话 + 逻辑事件标识/状态代次**；缓存与队列**必须有界**，
  且**不能按"同文本"删掉合法的重复**（同一句话重复说两次可以是两条合法事件）。
- **【裁决】诚实边界**：不承诺崩溃后严格 exactly-once（重启后已投递但未落盘的事件可能重播），
  文档与提示文案都不得暗示更强保证；**不恢复远程审批写回**。
- **【裁决】实施纪律**：去重 ID 在实现时**优先取用现有各源的真实 ID**（逐个源核实）；
  没有源 ID 时按上一条自建；**不编造**"上游给了 ID"的说法，也不为了让语义好看而倒推出一套 ID 体系。

## 四、无宠、退出、托盘与通知

- **【裁决】无宠时**：保留托盘、停止宠物驱动（渲染/物理/逐宠计时），**不自动复活**任何宠。
- **【裁决】退出应用与关闭宠物是两件事**：关闭最后一只宠不退出应用；退出应用是独立入口且需用户动作。
- **【裁决】退出应用保留活跃集合、重启后恢复**：显式退出**不改变**活跃集合（谁在谁不在照旧记着），
  下次启动按它恢复；改集合的只有"关闭宠物/生成宠物"（关闭 = 该槽留空），**退出应用不改集合**。
- **【裁决】无系统托盘时**提供**可见的恢复入口**（否则用户会永久无法唤回宠物）；**"没有托盘"不得成为
  拒绝"关闭宠物 / 整位留空"的理由**——关闭照旧可用，恢复入口必须另找**真正可见**的地方（主窗 / 岛 /
  设置页），**不得**用"关了就没入口"否决关闭，也不得因此拒绝生成 / 恢复。
- **【裁决】关闭主宠可逆 ⇒ 不得用"专属误操作确认"破坏主子公平**：关闭主宠 = 该槽留空，档案与位置保留，
  可再生成，**可逆**；因此"怕误点"不再是只给主宠加一道确认闸、让主宠与子宠在关闭路径上走**两套契约**的
  理由（G0 §1/§2.2 记录的 WP13 现状正是"主宠确认、子宠一键直退"）。**主宠与子宠的关闭契约必须同一语义**
  （要么同确认、要么同不确认）；确认框若保留，其理由只能是**语义差别**（主宠 = 整位留空，子宠 = 退一个席位），
  文案**不得**再写"不可逆 / 会退出应用"。**WP13 已验收冻结，本轮不动其代码**；G1 落地时按本节重定语义，
  并同步改按旧理由写的断言（例如托盘与右键菜单确认文案一致性的那几条用例）。
- **【裁决】全部隐藏 / 无宠时不暗开系统通知**：普通暂存**有界合并**；
  关键待处理状态可从**岛状态**或既有应用入口查到；**不做无穷补播**。
  **【现行】** 托盘入口与逐只菜单见 `pet/overlay_shell.py` 的 `_refresh_tray_menu` / `_exit_pet_from_tray`。

## 五、设置归属、reset 与并发写

- **【裁决】唯一归属表**：每个键归 **全局** / **每宠** / **运行态** 三者之一，且只有一处真值。
  `slot0` 的**每宠档案与全局配置拆开**；沿用现有命名 `config-slot-N.json`；活跃集合**版本化**并且**含 0**。
  实际类别如下（这是归属的实际划分，不是示意）：

  | 归属 | 实际类别 |
  |---|---|
  | **全局** | agent 联动、提示音、服务自启、灵动岛、语音报时 / 天气 / 待办提醒、捕获模式与 OS 开机自启、聊天连接（服务商与凭据） |
  | **每宠** | 角色、位置、尺寸、朝向、速度、物理（拖拽 / 重力 / 投掷）、点击、碰撞、声音（点击与碰撞音效）、气泡、自言自语；以及"碰撞资格" |
  | **运行态** | 显示目标、请求代次、隐藏状态；**活跃集合**（单独持久化，既不属于全局设置，也不属于任何一只宠） |

- **【裁决】"只有一处真值"是硬约束，"过渡期双份真值"不成立**：`slot0` 的每宠键迁进 `config-slot-0.json`
  之后，**同一键不得在 `config.json` 与 `config-slot-0.json` 同时作为有效真值存在**。历史读取方
  （legacy 单窗 / 捕获模式）若一时仍读 `config.json`，只能**从同一真值派生**读取；该派生是**本批次内**
  的实现与验收项——**不得**把"两份都可读可写"登记成文档里的长期状态，更不得留成 TODO 延期。
  规划稿（`.scratch/product-identity-plan-20261009/PLAN-G1-FIXED-IDENTITY.md` §5 R1）建议的
  "迁移只复制不删 + 过渡期双份真值"**不自动成立**：要么同批给出唯一读者与删除条件并纳入验收，
  要么改读取方，二选一，不许悬空。
- **【裁决】编辑权限**：任意宠**可以**编辑全局设置，但界面必须**明确说明影响所有桌宠**；
  "当前宠设置"只改该宠自身；主宠与子宠在设置面上**公平**（同一语义、同一可编辑性）。
  **不新增不必要设置项**；新增任何项先过 [`SETTINGS-CHANGE-GATES.md`](SETTINGS-CHANGE-GATES.md) 的准入与准出。
- **【裁决】「恢复默认」的作用域必须准确**：**全局 reset 不动任何每宠偏好**（保持既有 **AI 凭据保留**规则，
  `CHAT_SECRET_FIELDS` 不重置）；**本宠 reset 不动全局、也不碰别宠**。本宠 reset 重置的是**该宠的每宠偏好**
  （含**角色**与**尺寸**），但**保留位置**——"回到默认落位"是**独立操作**，不属于"恢复默认"。
  两种 reset 都**保留身份、保留活跃状态、保留会话历史**，确认框逐项写清实际范围。
  **这是工程默认口径，不冒称"用户逐项指定过"**：没有逐项确认记录时，文档与文案一律按本节表述，
  不得写成"用户已同意以下重置范围"。
  **【现行】** `pet/settings_slot_config.py` 的 `SlotRoutedConfig.reset_to_defaults` 已把子宠页重置闸在
  该宠 slot 文件上；`pet/settings_reset_defaults.py` 的 `reset_scope_is_slot` 驱动文案（WP13）。
  **【裁决，2026-10-09 冲突收口】**G0 实测：当前行为**不保留位置**，且 WP13 新增的两条文案/断言把这一
  旧行为钉死（`.scratch/product-g0-20261009/G0-WP13-ACCEPTANCE-REPORT.md` §1）。**本节语义不变**
  ——"保留位置"是对的；要改的是**行为**：G1 落地时把本宠 reset 的落盘键集去掉位置键、去掉 slot 作用域的
  "立即回默认落位"对齐，并同步改那两条断言与 `RESET_SLOT_*` 文案。**不得**为让现状自洽而回头改本节。
- **【裁决】不新增"清除档案"功能需求**；将来若要做，**清除 ≠ 关闭**（清除必须显式、可确认、不覆盖成他宠档案）。
- **【裁决】并发写**：所有写入者共享**短时锁 + 锁内 reload / 键合并 / 原子 replace**，
  或复用**既有单写者**机制；工程基准**优先最小目录级写锁**。
  **【现行】** 多进程碰撞/实例锁体系已在 Phase 4.4b 删除，`tests/test_architecture.py` 守住"退役模块不再出现"——
  **不得复活旧体系**。

## 六、捕获能力（OBS / 直播兼容）

- **【裁决】捕获能力当前只覆盖单宠**；它与**固定槽的持久状态分开**（捕获模式是运行形态，不是身份）。
- **【裁决】切捕获模式不得修改活跃集合、不得提升/降级任何身份**。
  **【现行】** `stream_capture_mode` 是重启级拓扑输入（`pet/overlay_settings_command.py`），
  走 legacy 单窗并拒绝生成，活跃清单保持不动。
- **【裁决】捕获模式下 `slot0` 空缺 = 没有捕获窗**（即 OBS Phase B 计划 §6.2 的方案 (a)）：捕获窗
  **跟随 `slot0` 的活跃状态**——`slot0` 活跃 → 存在可被 OBS 枚举的窗口；`slot0` **不活跃（用户关掉了它）
  → 窗口不存在**（不是"隐藏的空窗"）。**不得**为了让 OBS 有东西可捕而自动复活 `slot0`；UI / 设置页
  **必须明说**，否则用户会以为捕获坏了。该组合在 G1 落地前不可达（关最后一只 = 退出应用）。
- **【裁决】恢复入口与多宠禁令并存**：捕获模式下**托盘提供把 `slot0` 生成/恢复回来的入口**——这是
  **用户显式的"生成/恢复"动作**，允许；但捕获模式**仍禁止生成额外多宠**（子宠照旧被拒）。
- **【裁决】"切模式不改集合"与"关闭/生成改集合"不矛盾**：改活跃集合的只有**用户显式的关闭 / 生成**；
  勾选或取消捕获模式只是**重启级的运行形态切换**，本身**不改活跃集合、不改任何槽的身份**。两条并列成立，
  既不是规范内部冲突，也不是"二选一"。
- **【待实验】Phase B 的具体模式**（真实 WGC / BitBlt 等后端与参数）由实验选定；
  禁止在未取证前先在代码里"拍"一个后端。
