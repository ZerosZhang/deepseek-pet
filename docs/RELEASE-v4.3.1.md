## ⚠️ 升级说明

- 直接覆盖安装或换用新版便携版即可；配置目录不变。
- **本版有 16 个新增配置键，且没有「把老键搬走」的配置迁移**（此前这一条写成「无新增配置键、配置零改动」，自 #288 / #267 / #290 并入后已不成立，此处更正）：`pet/config.py` 相对 v4.3.0 净增 16 个键、**删除 0 个**，老键的名字 / 归属 / 默认值都没动。
  - **跨屏（1 个）**：全局键 `allow_cross_screen`（设置 → 常规 → 窗口与系统 → 「允许桌宠跨屏」），**默认关**、**重启生效**（合成窗壳在构造时快照一次，运行期不重读，与「直播捕获兼容」同口径）；默认关 = 窗口数、位置写入与拖拽行为与 v4.3.0 逐位相同。
  - **语音合成后端（9 个）**：`voice_chime_tts_backend`（**默认 `edge`**，可选 `edge` / `sapi` / `mimo` / `doubao`）、`voice_chime_tts_fallback`（默认开：主后端失败自动回退 edge）、`voice_chime_sapi_voice` / `voice_chime_sapi_rate`（Windows 本地 SAPI5 音色与语速）、`voice_chime_mimo_model` / `voice_chime_mimo_voice` / `voice_chime_mimo_style`、`voice_chime_doubao_speaker` / `voice_chime_doubao_pitch`。**默认值就是 v4.3.0 的行为**（edge + 自动回退），不选新后端等于什么都没变。MiMo / 豆包要自备 API Key，凭据放在**你自己的系统钥匙串**里（`dsh-pet-standalone` 条目下），**不写进 `config.json`**；钥匙串不可用（系统拒绝写入、或没有后端可用）时，值只落进**写它的那个进程**的内存：设置页默认跑在独立进程（`settings_process_isolation`），真正合成语音的服务在主程序进程，所以这条兜底在「设置页存、主程序用」那条链路上**等于没存**——**不承诺这次运行主程序能读到你刚填的 Key**；设置页会照实说「没能保存上（只在本进程内存，重启就没了）」，不会说成「已保存」或「本次运行有效」。（`keyring` 本体随**四个变体**的桌面包一起分发、`LICENSE` 与 `THIRD_PARTY_NOTICES.md` 一并进包，见 #294；这两条不再取决于你是否装了带 Chat 的变体。）
  - **节日（2 个）**：`festival_reminder_animation`（节日提醒是否播匹配动画，默认开）、`festival_birthday`（填上你的生日，当天会按「动态节日」排在最前；留空 = 没填）。
  - **每日一签（4 个）**：`divination_enabled`（总开关，**默认开**——抽签是你主动点的，不点不出声也不主动冒泡）、`divination_speak`（抽签时念解曰，**默认关**，开启后复用报时那条语音通道）、`divination_hint`（当天还没看时第一次点桌宠冒一行提示，默认开）、`divination_state`（**运行时状态**：今天抽到几号 / 本轮抽过哪些 / 签册；它随使用变动，不是给你手改的设置）。
- **语音与节日两页设置重新整理过**（键没搬，只是呈现）：语音页只把**当前后端**的参数字段平铺在最上面，其余后端各占一个「后端名（未启用）」的折叠头行、成员默认收起、换后端时其余端回到收起态；节日提醒页同样按后端/项目重新分区。原有开关的位置与默认值不变。
- **同一版另有一处「键名不变、取值放宽」，同样不需要迁移**：`music_player_paths`（手动播放器路径）认得的播放器从 2 个（网易云 / QQ音乐）扩到 4 个（+ 酷狗 / 汽水）。只有手改过 `config.json` 并往里写过 `kugou` / `soda` 键的人会看到差别——这些值此前会被清洗掉、现在会被保留。
- **从 v4.2.x 及更早升上来的，本页上面这几条（新增键、取值放宽、设置页呈现）都不适用**：那一步（升到 v4.3.0）会把主宠的每宠设置（位置、尺寸、角色、音效、气泡等）从 `config.json` 迁进 `config-slot-0.json` 并清掉旧键（迁移前留一份 `config.json.pre-slot0-migration.bak`），而**旧版本不读 `config-slot-0.json`**。升级路径、升级前备份与「怎么回退」见 [`../README.md`](../README.md) 的「升级」与「数据目录」两节，本页不重复。
- **这一步迁移的「源清理」口径本版更正过**（#289）：以前是「目标档案已存在时只验证备份、源里的每宠键留着不管」，现在**两条支都清源**——因为 `Config.save()` 本来就会在下一次保存时把全局身份里的每宠键无条件清掉，迁移侧「不清源」只会留下一个骗人的字段。清理前保证恢复路径真的留住了那批值：规范备份（`config.json.pre-slot0-migration.bak`）本来就是这批值就直接用；该路径已被**另一份快照**占用时**不覆盖它**，另存一份 `config.json.pre-slot0-migration-recovery-<毫秒>-<pid>.bak`；拿不到恢复副本就**不清源**并报失败。**源里没有每宠键时这一整段什么都不做**（不造文件、不写盘）——绝大多数从 v4.3.0 升上来的用户属于这种。
- 「拖动物理」「静止放手下落」等开关的默认值与 v4.3.0 相同，设置里的既有选择原样保留（观感变化见「修复内容」）。
- 设置页有一处**位置变化**：「直播捕获兼容」从「窗口与系统」组移出，单独成为「直播捕获（高级）」折叠组（设置 → 常规 → 直播捕获（高级））。键、行内文案与重启级语义都没变，只是换了分组、默认收起。
- 设置页有一处**新增**：「允许桌宠跨屏」这一行就在「窗口与系统」组里，排在窗口旗标类（置顶 / 全屏隐藏 / 光标穿透 / 直播捕获）之后；它标着「影响所有桌宠」，**在非合成窗拓扑（直播捕获兼容模式）下置灰**（那种拓扑下每只宠本来就是能被拖到别的显示器的真窗口，本键在那边没有读点）。
- 音乐设置页的「播放器路径（高级）」从 2 行扩成 4 行（网易云 / QQ音乐 / 酷狗 / 汽水 + 「自动检测」），右键菜单「音乐」的「打开…给主人放歌」入口同步从 2 条扩到 4 条；**这四条路径只影响启动哪个播放器，与歌词取词无关**（详见「修复内容」）。
- 从更早版本升上来的语音用户会注意到依赖下限变化：在线语音所用 `edge-tts` 的下限抬到 **7.3.1**（上限 `<8`），7.2.8 的中文 / 英文请求在本机实测都返回 403，7.3.1 正常（#287）。**打包版用户不需要自己装**：构建期有门禁核对 TTS 栈真的进了包（缺就中止构建），用的是随包那一份；只有从源码跑的人需要按 `requirements.txt` 装新版。
- macOS 用户升级后可见一处变化：切到别的应用时桌宠不再消失（#272，详见「修复内容」）。

## 🐛 修复内容

- **拖拽手感（单合成窗拓扑）**：拖拽恢复弹簧阻尼跟随（与旧版手感一致）；弹簧档松手不再瞬移到光标位置（就地起抛/落地）；慢速拖拽的亚像素步进也会实时上屏，不再一格一格跳；弹簧参数调活（滞后约减半、轻微过冲）。开关在设置 → 桌宠 → 动作与碰撞 →「拖拽与弹射」组 →「拖动物理」，默认关。
- **Markdown 渲染补齐**：快捷气泡（快捷提问/灵动岛问答）与经典聊天窗接入 Markdown 渲染，表格、代码块、列表与现代聊天窗同一口径。
- **主宠设置保存生效**（#271）：主桌宠设置页里的每宠设置（出图概率、气泡样式、点击朗读等）此前「保存成功但不生效、重开设置回默认值」——写入被静默丢弃。现已修复：主宠与子宠设置页走同一条保存通道，改动真实落到主宠档案并即时生效。
- **macOS：切到别的应用时桌宠不再消失**（#272）：macOS 上切到任何其他应用，整只桌宠会从桌面消失，点 Dock 图标激活回来才重新出现。根因是合成窗带 `Qt.Tool` 标志而 Cocoa 会在应用失活时把它 order out，而项目早在 legacy 单窗路径上打过补丁、**没有移植到合成窗新架构**——又因为合成窗是默认拓扑，绝大多数 macOS 用户走的正是唯一没打补丁的那条路。现已在合成窗构造期补下发同一平台属性：切到别的应用桌宠**保持可见**，z-order 与置顶语义不变。
- **桌宠「看得见但点不到」的穿透卡死**（#277）：某些情况下（典型是「锁定位置」单击后丢掉一次释放事件，例如 alt-tab / 模态抢焦点 / 屏幕迁移）桌宠会变成可见但完全无响应——单击、拖拽零反应，且点击无法自愈（点击本身被穿透吃掉）。根因是 click-only 按下留下的抓取状态没人收尾，导致整窗鼠标穿透态退不出去。修复后由看门狗收尾 + 穿透态多路收敛兜底解开；**用户手动开启的「鼠标穿透」不受影响**。
- **设置页更好找**（可见性打磨）：把「直播捕获兼容」从与「光标隐藏时自动穿透」同组的堆叠里拿出来，**单独成为「直播捕获（高级）」折叠组**（「光标隐藏时自动穿透」回到「窗口与系统」——它和置顶、全屏隐藏同族）；装得下的短页不再多余地摆出页内跳转条，页尾也不再空出一大块。
- **破坏性操作与作用域写明**：侧栏的两个重置按钮改为**「重置本宠设置…」/「重置全局设置…」**，不必点开确认框或读 tooltip 才知道点的是哪一个；「影响所有桌宠」这类作用域声明从说明文字末尾拆成标签行上的独立标注（说明全文与搜索索引照旧）；侧栏宽度按字体度量取最小值，1.5 倍字体下按钮文案不再被省略。
- **图标与对比度**：导航 / 保存并退出 / 重置 / 搜索框等图标此前是画死的位图，切主题不会自己变色，现按记录在切主题后重画；选中态对比度达标（浅、深两档都过了 WCAG 非文本对比线），`save` 不再与 `back` 共用同一个箭头字形；三端构建脚本此前漏送 `assets/icon.ico`（构建不报错、图标静默没有），打包版设置窗一直是系统通用图标——现按平台随包送入，设置窗设置自己的窗口图标。
- **截图问答的品牌图标**：标题栏的「截图问答」四字**改由固定的 DS logo 顶掉**（不随机、旁边不加第二个图标位；窗口标题与无障碍名仍保留这四个字，素材缺席时退回四字）；结果面板的加载动画**每一轮加载抽一次**（10% 鲸蛙、其余 DS logo；同一次操作连发的过程态算同一轮，整轮不换、不轮播）。同一片还收紧了跨截图的归属：被新一次截图顶下去的旧轮次不再覆写新卡片、也不再刷掉岛上与气泡里的那一行，面板上的图与文字保证来自同一次截图。
- **右键菜单的图标没有改**：菜单里的「截图提问」保持原来的矢量图标——试过的「鲸蛙上菜单」已撤回，菜单里不会出现鲸蛙（这一条如实写明，免得有人去菜单里找）。
- **酷狗 / 汽水「看不到歌词」**（多歌手取词）：两个播放器都已注册系统媒体控件、本来就能被识别到；真正丢词的是歌手名分隔符——酷狗报 `FLOW、GRANRODEO`（顿号）而歌词源返回 `FLOW/GRANRODEO`（斜杠），原先的整串比对匹配不上就丢词（网易云 / QQ 的多歌手曲目同样受影响）。现按分隔符把两侧都切成多段后**逐段相等**比对（`、` `/` `／` `&` `×` `,` `；` 与 `feat.` / `ft.`，两侧都加词边界，免得把 `swift`、`craft`、`Featherstone`、`FTIsland` 这类名字切开），且**只在两侧都呈多歌手形态时才走逐段比对**——整串命中的原有行为一个字不改。设置页「显示歌词」一行同时补上酷狗的开关位置（酷狗：设置 → 常规设置 → 播放 → 支持系统播放控件）与「酷狗 / 汽水无需填路径」。另：给这两个播放器单开一条「窗口标题取词」通道的方案论证后**不做**（汽水取不到标题，酷狗暂停时标题会串台）。
- **汽水音乐仍然取不到歌词的第二处根因：歌词请求走不出系统代理**（#291）：查到在播那首只有 QQ 源有词，而 QQ 源在本机**直连恒返回 HTTP 500**、改走系统代理则 200（同一分钟内实测）。修法是**直连仍然首选，只在「传输失败或 500 / 502 / 504」且这个 URL 确实存在另一条代理路、且剩余预算够用时回退一次**；`401 / 403 / 404 / 429 / 503` 不换路，带 `Retry-After` 的 5xx 也不换路；两路共用同一份 9 秒预算（实测不翻倍）。日志只记路线名、异常类型、HTTP 状态与 `Retry-After`，不回显代理地址、凭据与异常正文。**这一条不承诺「源里没有词或服务端拒绝也一定出词」**——有界回退只解决「这一路不通、另一路通」，不解决「两边都没有收录这首」。
- **右键菜单「音乐」从 2 个入口扩到 4 个播放器**（#285）：网易云 / QQ音乐 / 酷狗 / 汽水各有「打开……给主人放歌」，共用同一个 builder 与同一个启动 worker；设置页「播放器路径（高级）」相应给到 4 行路径 + 「自动检测」（检测只负责搜，不覆盖你手填的路径）。**这四条路径只影响启动哪个播放器，与歌词取词无关**——歌词读的是系统媒体会话（SMTC），所以「歌词不显示时改播放器路径没有用」已写进设置页每一行、检测行与 README 对应小节。
- **桌宠白色矩形色差**（帧序列透明底板，档位 `unblend-white-v5`，#292）：整只宠的矩形在白底上显出一块浅灰。根因是抠图把整块背景留成 `alpha = 1`（实测占整帧 82%，白底 255 被合成压成 254），而既有的 1 px 腐蚀够不到它（它铺满底板、邻域全是 1）。修法是在档链尾只把**恰好等于 1** 的 alpha 清成 0（RGB 一并归零；`alpha = 0` 与 `alpha ≥ 2` 一个位不动，发丝 / 抗锯齿过渡不受影响），档位串换成 `v5` 让旧世代失效。**这一条要求全素材都在 v5 上**：构建时有硬门比对档串（`scripts/check_frameseq_bundle.py`，三端构建脚本非零即中止构建），任何仍停在 v3 的素材都会被判陈旧并**拒绝出包**；所以**过了这道门的正式包里 106 个 clip 已经全是 v5**，运行时按包内帧序列直接采纳，**首次启动不会逐 clip 重出**。逐 clip 重出只发生在包里的帧序列**不是当前档**或**根本没有帧序列**时（从源码跑、或没过这道门就出包——后者已被门禁挡住）：那时先回退 WebM 播放，再由后台按启动预算补转。**本机已按新档全量重出过**（106 个 clip / 25,423 帧，2026-10-17 04:29→05:42 实测 **73m53s**、产物约 377 MB），重出后逐个 `meta.json` 的 `encoder` 都是 `…unblend-white-v5`、`unblend` 都是 `white-v5`（106/106），即本机素材树**不再有 v3 世代**；三端构建因缓存 key 变化同样会重出这一批，构建时长与包体都会跟着变。
- **每屏一张合成窗 + 逐宠跨屏**（#288，默认关）：开启「允许桌宠跨屏」并重启后，每块**有桌宠的**显示器各开一张合成窗，每只宠可以单独拖到别的显示器（搬一只，其余宠一个像素不动）；关着时全部宠只在启动那块屏、一张窗、拖不过缝。位置持久化语义定为「屏名 = 屏归属，只在**有意**把这只拖到另一块屏时才改写」——所以关掉开关、或某块屏临时拔掉，都**不会**吃掉已摆好的多屏布局，重新开启后各宠回到原来那块屏的原比例。**跨缝那一帧的跳位已在本 PR 内修掉**（根因是三条叠加：按光标落点提前移交、单矩形钳制域、移交顺序两次钳制；现改为「全部 overlay `advance` 之后按这一拍的**实际身体位置**移交 + **原子全局恒等换帧**（`旧原点+局部 == 新原点+局部`，弹簧目标 / 轨迹 / 速度不改）+ 跨缝期间的多矩形合法域（身体逐点落在相接屏并集内才合法）+ 邻窗只读投影」）。**位置连续是自动回归项**：`tests/test_overlay_seam_passage.py` 14 例里的「逐 tick 全局轨迹 == 同一块大屏的参考轨迹（`abs=0.001`）」与「移交帧全局恒等」钉住它，本机在 `main` 上 **14 passed**。**真双屏、混合 DPI 与显存占用仍未在本机验证**（本机只有一块活动屏）——跨缝的实机观感、异 DPI 混合缩放与投影的每 tick 合成代价都要一台真双屏机器才能验。
